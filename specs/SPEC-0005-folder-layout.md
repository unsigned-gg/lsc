# SPEC-0005-folder-layout

## Requirements

1. The scanner shall accept two specification layouts in one `specs/` directory: the flat layout `specs/NNNN-kebab-slug.md` and the folder layout `specs/NNN-kebab-slug/README.md` (CER-2936; the LeanSpec standard, "Statuses and layout").
2. A folder specification shall take its identity from its folder name. The folder name is its stem, and its number and slug come from the folder name.
3. The scanner shall apply R01 number uniqueness, R03 `depends_on` targets and the R11 catalog index to both layouts in the same way.
4. R04 shall require, for a folder specification, only that `README.md` contains an H1. For a flat specification, R04 shall still require that the H1 equals the file stem.
5. Other Markdown files inside a specification folder shall belong to that specification. The scanner shall not count, number or R04-check them as specifications.
6. A flat specification and a folder specification with the same number shall be an R01 duplicate.

## Design

### Folder names

A folder name matches `NNN-kebab-slug` or `NNNN-kebab-slug`: three or four ASCII digits, a hyphen, and a slug of lowercase ASCII letters, digits and hyphens. `parse_folder_name` returns the number and slug.

The `leanspec create` command writes three-digit folders, for example `001-my-first-feature`.

### Discovery

| Entry in `specs/` | Result |
|---|---|
| File `*.md` other than `README.md` | Flat specification; R01 checks its name |
| Directory whose name matches the folder pattern, with a `README.md` file | Folder specification |
| Directory whose name matches the folder pattern, without a `README.md` file | R01 error |
| Any other directory, for example `formal/` | Ignored |

The scanner does not read other files inside a specification folder, such as `IMPLEMENTATION.md`, as specifications.

### Identity and rules

| Rule | Flat `NNNN-slug.md` | Folder `NNN-slug/README.md` |
|---|---|---|
| Stem | file name without `.md` | folder name |
| R01 uniqueness | by numeric value across both layouts, so `001` and `0001` collide | same |
| R03 `depends_on` | target is any stem | same |
| R04 | H1 must equal the stem | an H1 must exist |
| R11 catalog link | `NNNN-slug.md` | `NNN-slug/README.md` or `NNN-slug/` |
| R12 relative links | resolve from `specs/` | resolve from the specification folder |
| Report file field | `specs/NNNN-slug.md` | `specs/NNN-slug/README.md` |

The R04 asymmetry is intentional. The `leanspec` tool writes a human title as the H1, for example `# My First Feature`, so an equality rule would fail every specification that the tool creates.

### Single-file commands

`lsc parse` and `lsc theorems` treat a path that ends in `NNN-slug/README.md` as a folder specification, with the folder name as its stem.
